# UI refactor: orchestration plan (2026-09-26)

Status: proposal and standalone, illustrative HTML prototypes only. No application code, training loop, or algorithm changes are authorized by this plan. See [index.md](index.md) for the four interactive concepts.

## Goal and boundaries

Enable research users to inspect historical, incomplete, and schema-incompatible experiments; compose arbitrary meaningful learning-curve comparisons (including Train + Test from one experiment); and move between discovery, analysis, details, and replay without a spreadsheet-first UI. Protect log provenance and operational controls. Changes may touch `src/ui/`, read-side bookkeeping, serialization boundaries, aggregation and tests under `src/marl/`, but **not training loops or algorithms**. Keep existing logs readable; never rewrite historical artifacts on inspection.

Existing paths to retain as reference: `src/ui/backend/server_state.py`, `src/ui/backend/routes/{__init__,experiments,results,runs,runners}.py`, `src/marl/models/{experiment,run,dataset}.py`, `src/marl/utils/stats/datasets.py`, `src/ui/src/components/{home/Home,home/ExperimentTable,home/MetricsPanel,Plotter,experiment/Experiment,experiment/MetricsTable,visualisation/EpisodeReplay}.vue`, `src/ui/src/{models/Results.ts,models/Experiment.ts,stores/ResultsStore.ts,main.ts}`.

## Findings that shape the order

- Listing parses every `experiment.json` in one request; an invalid file can fail the entire list. Inspect calls full `Experiment.load()` before showing the page; a removed trainer/environment class can therefore hide intact CSV results. `LightRun.reader` goes through `self.logger`, potentially constructing a writer or a network-backed logger while only reading.
- The current `/results/load` returns arrays of `Dataset` objects (`logdir`, `category`, `label`, `ticks`, `mean`, `std`, `min`, `max`, `ci95`). The results aggregator diagonally concatenates run frames and calls `.drop_nulls()` across every column; schema-evolved metrics can disappear. Source files are primarily per-run Train/Test/Training data CSV; actions JSON is a separate optional replay artifact, **not** an established JSON metrics format. The existing SQLite logger writes an `experiment.db` test schema but has no equivalent read adapter or complete Train/Training data writer.
- Home groups plots by `(category, label)`, then overlays only different experiments. `Plotter.vue` already renders several datasets but keys legend/visibility by `logdir`, so Train and Test of the same experiment collide. `DatasetTable.fromDatasets()` and `toCSV()` align unrelated arrays by index rather than tick. A chart's rounded bucket or wall-time x-coordinate must not be treated as a guaranteed replayable Test step.
- Prioritize an independent security gate: a read-only `TestClient` probe returned the repository README via encoded traversal through the SPA fallback in `src/ui/backend/routes/__init__.py`. Path-bearing operation routes accept client-provided paths without logs-root containment; destructive exploitation was **not** tested. `run()` binds to `0.0.0.0`, CORS allows all origins, and routes have no visible auth. Do not broaden deployment exposure before containment and access-policy review.
- Other concrete issues: `ServerState.new_runs` invokes nonexistent `src/start_run.py` (actual entry is `scripts/start_run.py`); the selected `dist_dir` is overwritten and serving from `src/` fails; `DatasetTable.columns()` fails on empty results; several async failure paths do not terminate loading/show local errors. The last two are code-path findings, not browser repros.

## Proposed read contract (design, not implementation)

- `ExperimentSummary`: stable server-controlled ID (not an unchecked path), display name, optional timestamp/config metadata, condition (`healthy` / `partial` / `unsupported` / `corrupt`), discovered run summaries, capabilities, diagnostics, source/provenance references. The server resolves IDs to canonical paths under its configured logs root. Define size/time bounds for reading malformed/large metadata, and document what can still be displayed with missing `experiment.json` or `run.json`.
- `ResultsReader`: probe source(s) deterministically and return normalized observations containing source run ID, category, numeric `time_step`, optional timestamp, metric-name/value and provenance; expose episode/action reading separately, without calling logging writers. Explicitly specify collision policy when formats coexist (no double-counting), null/non-numeric fields, missing ticks, and unsupported formats. Distinguish failures from empty data.
- Keep the current dataset response as a transition contract while plotting clients migrate; extend via a versioned response if adding warnings, sample counts or actual Test-step references. Prefer typed API schemas and fixture contract tests over frontend inference from partial `ExperimentSchema`. Control/write endpoints must require validated path, valid executable spec, and explicit capability/permission; **displayable does not imply runnable**.

## Four visual directions for a decision checkpoint

1. **Research studio (recommended):** quiet warm/light palette, typography-led experiment cards in a searchable left rail, large central chart canvas, context inspector and comparison tray; dense tables live in optional Data view. Best general balance for analysis + inspection; must manage density for hundreds of runs.
2. **Observatory:** dark, low-glare instrument panel with plot-first layout, metric dock, compact status readouts and focused replay view. Strong identity for signal inspection; requires high-contrast textual indicators, accessible non-color encodings and care for long config text.
3. **Run control room:** operational cards/status lanes and clear launch/stop/status controls; Analysis is a separate destination. Strong for active experiment management; extra navigation cost for primarily historical research.
4. **Replay atlas:** environment imagery, episode timeline and agent drawers lead; experiment tiles show trend previews. Strong for behavioral debugging, but highest workflow/preview cost and weaker initial entry point for aggregate curve comparison.

A theme change alone will not solve usability: both existing routes start with PrimeVue tables. Pilot the Research studio with real workflows, retain PrimeVue for optional dense data tables initially, and decide whether to remove it **after** interaction parity (sorting, pagination, selection, context actions) is established. Bootstrap and PrimeVue are separate dependencies; removal of one does not automatically remove the other. Preserve Chart.js unless evidence calls for replacing it.

## Validation and release checklist

- Backend fixtures: corrupt/missing/old metadata adjacent to intact entries; relocated directories and symlinks; partial CSV headers/rows; missing Test/Train/Training data independently; sparse and evolving metric columns across runs; no timestamps; unequal tick schedules; non-positive granularity; single-run and varying-per-tick CI; deterministic format conflicts; JSON/SQLite capabilities; no writer/network/file modifications during inspection.
- UI tests: malformed/missing optional DTO fields; list still visible when one entry breaks; spinner settles after each request failure; empty datasets; plot composition and category-specific visibility; colors/styles/legend; null points/unequal ticks/CSV; accurate replay link; stale/deleted experiment refs; deep links; run controls hidden or disabled for unverified entries. Add a frontend test runner (package currently only supplies `check` and `build`) and API route/contract tests; use an end-to-end browser smoke for the key workflows.
- Security: encoded traversal, `..`, absolute paths and symlink escapes on reads **and** write routes; bounded parsing; CORS/host/auth deployment policy; no raw internal paths in public errors. Ensure non-destructive test doubles for move/delete/start.
- At each milestone run focused tests, frontend type-check/build and then broader Python/frontend checks; capture baseline discrepancies separately. Use live `logs/` as read-only examples, and copies/synthetic fixtures for automated tests only. Release incrementally with compatibility endpoints or explicit migrations and documented fallback for unsupported historical formats.

## Confirmed decisions and remaining choices

- **Local-only UI:** design for a loopback-only service, not remote deployment. Still contain all paths and protect local write/control endpoints from cross-origin requests. No auth service is planned unless the scope changes.
- **Wall-time origin:** elapsed time starts at **each run's start**, not experiment creation or the earliest timestamp of a category across runs. Existing run metadata has no explicit start timestamp; for legacy logs, use the earliest valid timestamp across all available artifacts of that run as an **estimated** start and label the approximation. A run with no usable timestamps can still show step-based curves but should not silently appear on wall-time charts. Do not align Train and Test by array index.
- **Historical examples:** directories in `logs/` are available as read-only experiment-log examples; some lack `experiment.json`. Never change them while inspecting or prototyping. Prototype names come from these directories; prototype metric values and statuses are synthetic.
- **Choose a visual direction:** browse [the four examples](index.md) before starting UI implementation; Research studio remains the recommendation, not a locked decision.
- **Still to decide:** whether plot specs need persistence/share links in the first release (default session-local); provide representative JSON metrics/SQLite samples before promising support for undocumented formats. CSV and raw JSON inspection can begin now.

Audit note: a delegated agent ran `npm run check -- --noEmit --incremental false` successfully and reproduced the SPA traversal and cwd serving issues with read-only TestClient requests; no destructive endpoints or training were run. Other listed issues are source-based until covered by new regression tests.
